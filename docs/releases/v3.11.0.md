# v3.11.0 upstream sync

Synced from [du2333/flare-stack-blog v3.11.0](https://github.com/du2333/flare-stack-blog/releases/tag/v3.11.0), commit `0ac5b3e4500b98c87fea6a1a32da215a5f198aa1`. See the [upstream comparison](https://github.com/du2333/flare-stack-blog/compare/v3.10.0...v3.11.0) for the complete change set.

## Changes

- Moments: short public entries at `/moments`, with up to 1000 characters and either up to 50 images or one Direct Video, Bilibili video or YouTube video. Admins can create, edit and delete them on the public pages, with local draft recovery and save-token conflict protection.
- Moment comments reuse the Post comment rules, notifications and Admin reply queue. Moments have their own RSS, Atom and JSON feeds and appear in the sitemap.
- Post comment notifications use the published title and address. Missing comment links fail immediately after a refused lookup, and muted-user notices occupy their own line.
- The HTTP API, generated contract and bundled Agent Skill include Moments.

## Upgrade from v3.10.0

Apply these migrations, in order, before deploying the new Worker:

1. `0032_moments.sql` creates `moments` and `moment_images`.
2. `0033_moment_comments.sql` rebuilds `comments` with exactly one Post or Moment target. Existing comment IDs, content, thread relations, status, timestamps and indexes are retained; a Moment comment index is added.

`bun run deploy` applies D1 migrations before publishing the prebuilt Worker. The fork's GitHub Actions deployment also runs `bun run db:migrate` before `cf deploy`. For local development, use `bun run db:migrate:local`. This source sync does not apply migrations to a deployed database.

Webhook comment events gain `target` (`post` or `moment`). Existing fields remain; for Moment comments, `postTitle` is derived from the beginning of the Moment's text. Consumers should use `target` to distinguish them.

The OpenAPI Edit Conflict components are now `PostsEditConflictError` and `MomentsEditConflictError`. Regenerate clients that refer to the former component name. Moment updates send the latest `saveToken`; stale saves return `EDIT_CONFLICT`.

## Fork integration

- The `default`, `fuwari` and `cuckoo` themes, build-time `THEME` selection, theme registry, Site Config fields, static resources and image preloads are retained (ADR 0027).
- The Theme Contract now includes Moment timeline/detail pages and skeletons. Themes reuse upstream Moment cards and management workflows, with their own layouts and comment components. Cuckoo keeps its avatar, accent and glass surfaces; the default theme keeps its content width and surfaces.
- Moments navigation is visible to readers only after the first Moment exists, and always to Admins. Latest Moments appear in the Fuwari/Cuckoo home sidebars and the default theme's home content.
- All themed comment components accept a Post or Moment target and resolve `?comment=` links, including threads and replies outside the initial page. Theme-specific editors and rendering are preserved.
- Fork deployment/secrets preparation, local Markdown issue tracking and theme-specific translations are retained. `package.json` is `3.11.0`; build, OpenAPI, update checks and Agent Skill download links derive their version from it. Upstream made no dependency or lockfile changes in this release. The fork explicitly declares the default theme's existing Noto Sans SC and Noto Serif SC imports at the locally installed `5.2.10` versions, so clean installs retain its typography; all other locked versions remain unchanged.
